## Using the website

1. Choose **迴歸探索器**, then select either regression problem and a method/K.
2. Review validation curves, OLS coefficients and live predictions. Test
   diagnostics are restricted to the K chosen by validation performance.
3. Choose **自訂 Dataset** to upload a CSV or load an approved public CSV URL;
   select the numeric target and predictors, then start browser-only analysis.
4. Choose **原始 32 模型研究** for all four loss objectives and the original
   best model’s calibrated prediction interval.

If an old tab shows “Site not found” after deployment, allow propagation and
perform a hard refresh (Ctrl+Shift+R). For actual workflow failures, inspect the
red failed step instead of treating yellow maintenance notices as errors.

## Enable the site (repository administrator)

The static website is in `web/`. No Streamlit hosting, paid server, API token or
secret is required. The existing Streamlit application remains available.

1. Open repository **Settings → Pages**.
2. Under **Build and deployment → Source**, choose **GitHub Actions**.
3. Open **Actions → Deploy Regression Studio to GitHub Pages**. If the initial
   run failed before Pages was enabled, open that run and choose **Re-run all jobs**.
   The deployment workflow is on `feat/final-regression-explorer`; a
   `workflow_dispatch` button may not appear until the workflow is merged into
   the default branch. Re-running the push-triggered run works without merging.
4. If GitHub reports a deployment branch restriction, open **Settings →
   Environments → github-pages → Deployment branches and tags** and allow
   `feat/final-regression-explorer`. Do not bypass any organization approval rule.
5. The successful deployment job supplies the actual site URL, expected to be:
   `https://meryan-421.github.io/appliances-energy-feature-loss-comparison/`.

Both `main` and the development branch can trigger deployment on web changes.
The prepared change does not merge into or overwrite main. After merging the
feature branch, main can continue deploying the same website.

Enabling Pages and successful Actions execution are prerequisites. A pushed
workflow alone does not establish that the site is live. In this environment,
GitHub's API domain is blocked by the network proxy, so administrator settings
and the deployment outcome cannot be changed or confirmed through that API.
Never supply passwords or tokens in chat.

## What runs where

- The public page is static HTML/CSS/JavaScript with locally bundled Chart.js
  4.4.8 (MIT license retained). There is no Python server to keep running.
- Both predefined problems have precomputed JSON payloads generated by the same
  independent regression workspace used by Streamlit. In-browser predictions
  use exported coefficients and the actual fitted preprocessing schema.
- Original 32 configurations, four loss functions, best-model metadata and
  calibrated interval are exported read-only from the preserved research.
  The best bundle is never unpickled from user input.
- Custom CSV training uses Pyodide 0.27.7 in a Web Worker, with numpy 2.0.2,
  pandas 2.2.3, scipy 1.14.1 and scikit-learn 1.6.1 from the pinned official
  Pyodide distribution on cdn.jsdelivr.net. Package integrity verification
  remains enabled. Static exports use native scikit-learn 1.9.0. Versions are
  disclosed because results can differ slightly across runtimes.
- The worker reuses copies of `app/utils/regression.py` and
  `scripts/pages_payload.py`; `scripts/export_pages.py` refreshes these copies.
  Tests ensure copies match their sources.
- Uploaded CSV contents and trained custom models stay in browser/worker memory.
  No analytics, storage endpoint or public upload is used. Reloading or clearing
  removes the workspace. Users fetch public CSV URLs directly with CORS; only
  raw.githubusercontent.com HTTPS CSV URLs are allowed, with redirects rejected.
- Input limits: CSV 5 MB; 20–3,000 rows; at most 40 raw columns / 20 encoded
  predictors. SFS/exhaustive: at most 1,000 training rows / 8 encoded predictors.
  A 180-second worker timeout and stop button limit expensive requests.
- First custom training downloads scientific runtime components (tens of MB).
  Ordinary exploration and prediction do not require that runtime. If a network
  blocks the CDN, predefined problem and original-research pages still work;
  custom training reports an error and can be retried.

K selection uses validation RMSE, never test results. Test diagnostics show only
the validation winner for each method. Training OLS inference is explicitly
separated from validation metrics. Post-selection p-values are descriptive,
not causal evidence. Rank-deficient fits suppress classical inference. K counts
transformed columns including categorical dummies. Original split-conformal
intervals are not reused for newly fitted models.

## Rebuild and test

From the repository root with the Python environment installed:

```bash
# Ensure the ignored public Appliances CSV has been provisioned.
bash scripts/validate.sh
OPENBLAS_NUM_THREADS=2 .venv/bin/python scripts/export_pages.py
node scripts/test_pages_core.mjs
.venv/bin/python -m unittest discover -s tests -v
python3 -m http.server 8765 --directory web
```

In another terminal, optional real-browser checks require Playwright and Chromium:

```bash
.venv/bin/python -m pip install playwright
.venv/bin/python scripts/pages_browser_smoke.py
```

Set PAGES_URL and CHROMIUM_PATH to override local defaults. PAGES_TEST_PROXY=1
routes external browser requests through Python's configured, TLS-verifying
HTTP proxy in restricted execution environments; it does not disable browser or
package verification. This test covers problem and K switches, original model
prediction, CSV upload, browser Python training, URL loading, and mobile width.

Generated payloads are public reference data, not user uploads. Never copy
uploaded files into `web/`. `web/data/provenance.json` records the source hashes
and native sklearn version. To update original research, do a separate reviewed
experiment task rather than running the original engine during deployment.
